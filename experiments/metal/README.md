## Performance and fallback behavior

- MP4: 15,836,092 bytes, 1920×1080, 24 fps, H.264 4:2:0, no audio, six-frame GOP, no B-frames, faststart.
- Posters: 200,892 and 157,214 bytes, full-width source resolution.
- One video element and one outstanding seek; a 0.35-second GSAP scrub smooths wheel steps, and rapid input replaces the pending target. Stop scheduling and suspend watchdogs when hidden. Nothing animates perpetually while idle.
- HTTP byte ranges; no full video buffering in JavaScript and no hundreds-of-images decoded cache.
- Small touch screens (up to 700 CSS pixels AND coarse pointer), reduced motion, JS/library failure, or a persistent media failure: composed static opening with readable content. Transient media failures get one automatic retry. Late data and returning to a visible tab restore requested motion; an explicit manual pause is respected. Narrow desktop preview panels still get motion. Touch/reduced-motion visitors can explicitly opt in with Spustiť animáciu; failed media can also be retried manually. Mobile does not download video before opting in.
- Shared GSAP/ScrollTrigger browser distribution pinned by package-lock integrity, following the existing isolated prototype approach. No competing smooth-scroll engine or Next package installation.
